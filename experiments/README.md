# 모델 비교 실험 기록

오답노트를 만드는 모델로 가장 저렴한 Claude Haiku를 써도 되는지 확인하려고 한 실험이다. 날짜는 2026-11-15.

## 질문

노트에서 가장 중요한 것은 "내 코드가 어디서 왜 틀렸는지"를 정확히 짚는 것이다. 틀린 진단이 적힌 오답노트는 없느니만 못하다. 그래서 Haiku, Sonnet, Opus 세 모델에 같은 지시문과 같은 자료를 주고 진단이 맞는지 비교했다.

## 방법

1. 버그를 숨긴 문제를 직접 만들었다. 버그 코드는 예제를 통과하지만 다른 입력에서 실패한다. 이 점은 정답 코드와 무작위 입력으로 비교해 미리 확인했다.
2. 모델에는 문제, 버그 코드, 증상("예제 통과, 제출 시 오답" 등)만 주고 원인은 알려 주지 않았다. 코드 실행도 금지했다.
3. 모델이 낸 답을 세 가지로 채점했다.
   - 원인을 정확히 짚었는가
   - 모델이 제시한 실패 입력이 실제로 실패하는가 (직접 실행)
   - 모델이 낸 수정 코드가 정답인가 (정답 코드와 무작위 입력 수천 개로 비교)

## 문제

| 문제 | 숨긴 버그 | 증상 | 파일 |
|---|---|---|---|
| A. 리본 자르기 | 이분 탐색에서 중간값을 내림으로 계산해 범위가 2칸 남으면 무한 반복 | 시간 초과 | `problems_ab.py` |
| B. 통행료 쿠폰 | 최단 경로에서 "쿠폰 사용 전/후" 상태를 거리 배열 하나에 섞어 기록 | 일부 오답 (무작위 입력의 20%) | `problems_ab.py` |
| C. 구간 최솟값의 합 | 단조 스택의 양쪽 경계를 모두 `>=`로 잡아 중복 값이 있으면 이중 계산 | 절반 이상 오답 | `problems_cd.py` |
| D. 스터디카페 요금 정산 | 서로 무관한 버그 2개: 회원번호 문자열 정렬, 올림 계산 `// + 1` | 일부 오답 | `problems_cd.py` |

이보다 앞서 쉬운 문제 하나(학습자가 이미 통과한 풀이를 정리하는 과제)도 돌렸고, 세 모델 모두 사실 오류가 없었다.

## 결과

| 항목 | Haiku | Sonnet | Opus |
|---|---|---|---|
| 원인 진단 (A, B, C, D) | 4/4 | 4/4 | 4/4 |
| D의 버그 2개를 모두 찾음 | 예 | 예 | 예 |
| 제시한 실패 입력이 실제로 실패 | 4/4 | 4/4 | 4/4 |
| 수정 코드 정답 | 4/4 | 4/4 | 4/4 |
| 부가 설명의 사실 오류 | 2건 | 0건 | 0건 |
| 작성 시간 (A / B / C / D, 초) | 26 / 51 / 29 / 27 | 26 / 32 / 38 / 30 | 32 / 59 / 49 / 36 |

Haiku의 사실 오류 2건은 모두 "다른 풀이 방법" 항목에서 나왔다.

- B: 대안으로 "BFS 또는 다익스트라"를 적었다. 통행료가 제각각인 문제라 BFS는 쓸 수 없다.
- C: 대안으로 든 DP 풀이에 대해 "기준을 틀리면 같은 오답이 난다"고 적었다. 실제로는 어느 기준이든 정답이 나온다 (`grade_cd.py`에서 확인).

## 결론과 반영

- 핵심인 원인 진단과 수정 코드는 세 모델이 같았다. 차이는 부가 설명의 정확도와 깊이에서 났다. 그래서 기본 모델을 Haiku로 정했다.
- Haiku의 약점을 줄이려고 지시문(`../prompt.md`)에 "다른 풀이는 이 문제의 조건에서 실제로 성립하는 것만 적을 것"을 넣었다.
- 모델 이름은 `../config.json` 한 줄로 바꿀 수 있게 했다.

## 한계

- 표본이 4문제다. 통계적으로 의미 있는 비교가 아니다.
- 문제를 직접 만들었고, 버그가 알고리즘 공부에서 비교적 알려진 유형이다. 더 낯선 버그나 지문이 긴 실제 문제에서는 결과가 다를 수 있다.
- 모델당 한 번씩만 돌렸다. 같은 입력에도 답이 매번 조금씩 달라지므로 반복 측정이 필요하다.
- 모델의 설명 품질(이해하기 쉬운가)은 사람이 읽고 판단했다.

## 다시 실행하기

```bash
python3 problems_ab.py   # A, B: 버그 코드가 실패하는 비율 확인
python3 problems_cd.py   # C, D: 같은 확인
python3 grade_cd.py      # C, D: 모델이 낸 실패 입력과 수정 코드 채점
```
